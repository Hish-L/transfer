transfer

files over light

One screen displays a file as an endless stream of QR codes. Another device points a camera at it and rebuilds the file. There is no network path between them — no Wi-Fi, no Bluetooth, no pairing, no account. The bytes cross as light.

■□■ Send → Pick a file on this device and start the stream. Up to %MAX_FILE_LABEL%. ◉ Receive ← Open the camera and point it at a sending screen.

From a terminal

The sender also runs in a terminal — it draws the QR stream with half-block characters and any phone can read it off the glass. macOS and Linux, python3 and nothing else.

curl -fsSL https://hish-l.github.io/transfer/qr.sh | bash -s -- myfile.pdf

Piping a URL into a shell is trust-on-first-use of this origin. If you would rather look first: curl -fsSLO https://hish-l.github.io/transfer/qr.sh && less qr.sh, then bash qr.sh myfile.pdf.

How it holds together

A camera pointed at a screen is a one-way link: the receiver has no way to ask for a frame it missed. So the sender never waits to be asked. It emits an endless stream of fountain-coded frames — each one a random XOR of source blocks — and the receiver rebuilds the file from any sufficient set, in any order. Dropped, blurred, duplicated and out-of-order frames cost time and nothing else.

Filename and media type survive the trip. Compression is applied only when it actually helps. Nothing is offered to you until its SHA-256 matches.

What this is not

It is not encrypted. Whatever is on the sending screen is readable by any camera pointed at it, including one you did not notice. The property you get is no network, not confidentiality. Encrypt the file first if that is what you need.
